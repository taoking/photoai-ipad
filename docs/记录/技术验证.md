# M0 技术验证

> 2026-11-21，分支 `m0-spike`。回答 [开发计划](../开发/开发计划.md) §6 的四个问题。
> 设备：iPad Pro 11 英寸（2018，iPad8,1，A12X），**iPadOS 26.7.3**（文档原来写的 26.6）。构建：Xcode 27.0，部署目标 26.0，Release。
> 卡：用户的索尼 A7C II 卡（和 Mac 版 M1 验收用的同一张），`DCIM/100MSDCF`、`101MSDCF`，2,148 组 ARW + JPG，共 164 GB。通过 USB-C 读卡器接 iPad。
> 证据：应用写的日志 `Documents/技术验证日志.txt`，用 `Scripts/pull-log.sh` 拷回 Mac；下面引用的数字都出自这份日志（日志本身含卷 UUID，不进仓库）。真机上的操作由用户完成。
> 测量代码：`App/Spike/CardProbe.swift`。预览生成照搬 Mac 版 `ImageDownsampler` / `PreviewGenerator` 的做法（内嵌预览够大就用，先写 1600 再从它缩 480，JPEG 质量 0.82）。

## 结论

| 问题 | 结论 |
| --- | --- |
| 1. 书签能不能留住 | **能。** 拔卡后解析直接报错（不会误报“已连接”），插回同一张卡后同一个书签又能用，`stale=false`；重启 iPad、覆盖安装后书签都还能用。冷启动时偶尔暂时解析不了（-2001），过一会儿就好（§1.2）。格式化后的卡没测（NOT RUN）。 |
| 2. ImageIO 能不能读 ARW / JPG | **元数据都能读**，相机、拍摄时间、亚秒都在，20 + 20 张没有缺拍摄时间的。**但 iPadOS 的 ImageIO 不解 RAW**：ARW 在 ImageIO 里就是它内嵌的 1616×1080 JPEG（属性里的宽高也报 1616×1080）。真正解 RAW 要用 `CIRAWFilter`（支持 ILCE-7C II），缩到 1600 要 8.9 秒、内存峰值 347 MB，不能用于预览。 |
| 3. 速度、内存 | 列整张卡 4,296 个文件（含大小和修改时间）5.2 秒；EXIF JPG 每张 12 ms、ARW 29 ms；预览（1600 + 480）单线程 JPG 167 ms、ARW 87 ms，4 并发折合每张 19–25 ms；对焦框每张 0.5–1.3 ms。除了 `CIRAWFilter` 那一次，内存一直在 33 MB 左右。 |
| 4. 轮询书签值不值得 | **值得。** 一次检查（解析 + 开始访问 + 列 DCIM + 停止）平均 7.7 ms，每 3 秒一次的开销可以忽略；拔卡、插卡都在一个周期内发现。 |

## 1. 书签

### 1.1 选卡、存书签

- 选择器里选卡的根目录，得到的路径是 `/private/var/mobile/Library/LiveFiles/com.apple.filesystems.userfsd/<卷 UUID>`，`startAccessingSecurityScopedResource` 返回 true，存书签 27 ms。
- iPadOS 上 `bookmarkData(options: [])` 就够了（没有 macOS 的 `.withSecurityScope`），解析出来的 URL 要先 `startAccessing…` 才能读。

### 1.2 拔卡、插回、重启

前台轮询开着，用户拔卡、等几秒、插回（日志 21:51:46 – 21:51:59）：

| 时间 | 状态 |
| --- | --- |
| 21:51:46 | 已连接（27 ms） |
| 21:51:53 | 拔卡后：**解析书签直接失败**，`NSFileProviderErrorDomain -2001`“找不到使用标识符 com.apple.filesystems.UserFS.FileProvider 的有效文件提供者” |
| 21:51:59 | 插回：已连接，`stale=false`，路径不变（这次 334 ms，卡刚挂上） |

重启 iPad 后（第 2 次启动，21:54:00）：

- 启动那一刻和回到前台时，解析都报同样的 -2001；
- 35 秒后用户打开轮询，第一次检查就“已连接”，`stale=false`，路径不变。

所以重启后书签照样能用。用户确认当时是“先插卡再打开应用”，卡一直插着。

第一次覆盖安装后打开（第 3 次启动，21:57:06）又出现同样的 -2001，卡也一直插着。于是加了“启动后每秒重试一次、最多 30 秒”的日志，第二次覆盖安装后用户从多任务里划掉应用、重新打开两次（第 4、5 次启动，22:00:30、22:01:27）：**两次第一次解析就连上了**（33 ms、31 ms），没能复现。

推测是系统的外接存储服务（`com.apple.filesystems.UserFS.FileProvider`）有时还没起来，什么时候会这样不确定。**对 M1 的影响：一次解析失败不能当成“这张卡不行了”去清书签或马上弹选择器**，前台一直轮询，等它自己连上；只有用户点“读取存储卡”、而且书签确实连不上时才打开选择器。

### 1.3 覆盖安装

`reinstall.sh` 先后覆盖安装了两次（构建 202611212143 → 202611212156 → 202611212158），每次装完 `Application Support/PhotoAI/spike/launches.txt` 都还在、接着记：第 3 次启动显示“首次启动记录：21:49:41 构建 202611212143”“书签文件在”，第 4、5 次书签直接能用。**覆盖安装保留数据。**

- 描述文件没换（同一个 UUID），签名到期日一直是 2026-11-28 21:43（北京时间）。
- `devicectl device process launch` 从 Mac 上打开应用一直被拒（“profile has not been explicitly trusted”），在 iPad 上点图标能正常打开。`reinstall.sh --launch` 失败时只提示，不算安装失败。

## 2. ImageIO 和 RAW

第一张样片 `DSC08857`（70-200 GM II，方向 8）：

| | JPG | ARW |
| --- | --- | --- |
| 类型 | `public.jpeg` | `com.sony.arw-raw-image`，图像数 1 |
| DateTimeOriginal / Subsec | 2026:07:19 20:32:14 / 974 | 相同 |
| ImageIO 报的宽高 | 7008×4672 | **1616×1080**（内嵌预览的大小） |
| 内嵌预览 | —（JPG 没有大内嵌图，走完整解码缩小） | 1080×1616，取出来 71 ms |
| 读 EXIF（20 张） | 平均 12.2 ms（7.9 – 27.6） | 平均 29.4 ms（17.2 – 243.7） |

- `CGImageSourceCreateImageAtIndex` 对 ARW 13 ms 就返回了 1616×1080，也就是内嵌 JPEG，不是解 RAW。和 macOS 不一样（Mac 上 ImageIO 会完整解码）。
- `CIRAWFilter.supportedCameraModels` 里有 “Sony Alpha ILCE-7C II”。打开 83 ms，原始尺寸 7008×4672；缩到 1600 输出用了 **8.9 秒**，进程内存峰值 **347 MB**（其他步骤都在 33 MB 左右）。

对后面的影响：

- **合组不受影响**：拍摄时间、亚秒、型号从 ARW 都能读到。
- **照片的宽高不能从 ARW 取**（M1）：有 JPG 用 JPG 的，只有 ARW 时用 `CIRAWFilter.nativeSize`，或者读 EXIF 里的 `PixelXDimension`，M1 实测哪个对。
- **100% 放大（F-13）、单张换原图（F-16）只能用 JPG**，和功能列表的“JPEG 优先”一致；只有 ARW 的照片最大只能看 1616 px。A7C II 平时 RAW + JPEG 一起拍，影响小。
- 预览来源：ARW 内嵌图（1616 px，是相机按创意外观渲染出来的）做 1600 预览比 JPG 快一倍（见 §3）。用户选了 **ARW 内嵌图优先、没有 ARW 用 JPG**（Q5），功能列表 F-04 已改。

## 3. 速度和内存

| 项目 | 结果 |
| --- | --- |
| 列 DCIM（递归，取大小和修改时间） | 4,296 个文件 5,225 ms（Mac 上重扫同一张卡 0.59 秒）。PF-4（1,000 张未变化 ≤ 3 秒）按比例约 1.2 秒，够 |
| 读 EXIF | JPG 12.2 ms、ARW 29.4 ms / 张 |
| 预览 JPG，单线程 | 167 ms / 张（131 – 263），写出 1600 + 480 共约 319 KB |
| 预览 ARW，单线程 | 87 ms / 张（78 – 111），约 293 KB |
| 预览 JPG，2 / 4 并发 | 折合 44 / 25 ms / 张 |
| 预览 ARW，2 / 4 并发 | 折合 38 / 19 ms / 张 |
| 对焦框 | JPG 1.3 ms、ARW 0.5 ms / 张；40 张都读到了 |
| 内存 | 启动 9 MB，测量中 33 – 39 MB；峰值 347 MB 只出现在 `CIRAWFilter` 那一次 |
| 温度 | 全程“正常” |

注意：

- 并发那几行是**同一批文件第二、三遍读**，卡上的数据已经在系统缓存里，比冷读快，不能直接乘张数。单线程那两行是第一次读，比较接近真实。
- 对焦框 20 + 20 张读出来的第一张中心都在 (0.500, 0.500)。可能这批照片用的是中心对焦，也可能读法对这台机器有问题；P1 做对焦框（F-18）时要对着照片目视核对，不能只看“读到了”。

**PF-5 估算（整张卡首次导入，2,148 组）**：列目录 5 秒 + EXIF 约 2,148 ×（12 + 29）ms ≈ 90 秒（可以并发）+ ARW 内嵌图出预览单线程 2,148 × 87 ms ≈ 3 分钟、并发预计 1 – 2 分钟。比计划里估的“十几分钟”快得多，M1 实测。

## 4. 轮询

- 100 次“解析 + 开始访问 + 列 DCIM + 停止”：平均 7.7 ms（5.4 – 38.0），全部能访问。
- 每 3 秒一次，CPU 占用约 0.3%，可以忽略。
- 拔卡、插回都在一个周期（3 秒）内发现。

**决定（用户选了“做，插上自动重扫”，Q6）**：M1 做“插上就自动读”——前台每 3 秒检查一次书签，从“未连接”变“已连接”时自动重扫。F-01 的“点读取存储卡”保留，用来第一次选卡和书签确实不行时重选。

## 5. 没测的

- 格式化后的卡能不能用旧书签（NOT RUN）：没必要为这个格式化一张有照片的卡。预计不能（卷 UUID 会变），到时候在选择器里再选一次就行。
- 冷状态下整张卡的导入耗时：放到 M1，用真实扫描代码测 PF-5。
